# Local Agent LLM Enhancement Guide

## Introduction

The Local Agent supports using Large Language Models (LLM) to enhance its natural language understanding capabilities.
By default, the Agent uses a rule-based engine (Regex/Keywords) to parse user intents, ensuring underlying stability and zero cost.
Enabling LLM allows the Agent to understand more complex, vague, or multi-step natural language instructions.

## Configuration Method

The Local Agent reads the `.env.local` file in the `apps/local-agent` (or `packages/agent` depending on deployment) directory.

### 1. Alibaba Cloud DashScope (Qwen)

```env
# Provider type
LLM_PROVIDER=qwen

# API Key (Required)
DASHSCOPE_API_KEY=sk-xxxxxx

# Model Name (Optional, defaults to qwen-max)
DASHSCOPE_MODEL=qwen-max

# API Endpoint (Optional, usually default)
# DASHSCOPE_BASE_URL=...
```

### 2. OpenAI / Compatible (Beta)

```env
# Provider type
LLM_PROVIDER=openai

# API Key
OPENAI_API_KEY=sk-xxxxxx

# Model Name
OPENAI_MODEL=gpt-4o
```

## Safety Mechanism (Guardrails)

Even with LLM enabled, the Agent strictly adheres to the following safety principles:

1.  **Intent Whitelist**: LLM output must map to a pre-defined set of legal intents (e.g., `MINT_AND_PAY`, `BURN`, `CLAIM`). Unknown intents are rejected.
2.  **Parameter Extraction Only**: LLM is only responsible for extracting parameters (e.g., amounts, product names) from text and **cannot** invent non-existent parameters.
3.  **No Private Key Contact**: LLM **never** touches any wallet private keys or sensitive data.
4.  **Human Confirmation**: All transactions generated by LLM parsing **must** be confirmed by standard wallet signature processes.

## Debugging

When LLM is enabled, you can view the raw response and parsing process of the LLM in the terminal logs of the `local-agent` service.

```bash
[LLM] Requesting Qwen: "Help me buy a coffee"
[LLM] Response: { intent: "CREATE_INVOICE", slots: { product: "coffee" } }
[Agent] Parsed Intent: CREATE_INVOICE
```
