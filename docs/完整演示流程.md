# 稳流支付站完整演示流程（开源项目版）

> 目标：在 8-12 分钟内完整展示“商户建单 -> 用户一键支付 -> 赎回 -> 商户 Claim -> 指标验证 -> Agent 自动化剧本 -> 本地自治任务执行”。

## 1. 演示前准备

1. 启动项目：

```bash
corepack pnpm install
corepack pnpm dev
```

2. 打开：`http://localhost:5173/#/quickstart`
3. 连接钱包并确认 `.env` 已配置：
   - `VITE_PACKAGE_ID`
   - `VITE_MERCHANT_ID`
   - `VITE_STABLE_LAYER_STABLE_COIN_TYPE`
   - `VITE_STABLE_LAYER_BRAND_USD_TYPE`
   - `VITE_STABLE_LAYER_USDC_TYPE`

## 2. 先讲清“真实模式 vs Smoke 模式”

- 默认是 **真实链模式（REAL）**。
- 只有 URL 包含 `?smoke=1` 时才进入 **Smoke 演示模式**。
- Quickstart 的“链路健康状态”卡片会明确显示当前模式。

说明建议：
- `REAL`：所有余额、checkpoint、交易链接都来自真实 RPC。
- `SMOKE`：用于离线流程演示，交易反馈是模拟，不作为链上真实性证明。

## 3. 主线演示（手动版）

### 3.1 商户建单（`#/merchant`）

1. 进入“商户台”。
2. 创建 Product（标题 + 价格）。
3. 选择 Product 创建 Invoice。
4. 在账单列表点击“去支付页”。

验收点：
- 出现新的 `Invoice objectId`。
- 状态为“待支付”。

### 3.2 用户支付（`#/pay/:invoiceId`）

1. 切换到买家钱包。
2. 看“一键支付预览”：
   - 预计铸造
   - 预计支付
   - 已选 USDC 总额
   - USDC 对象列表
3. 点击 `USDC 一键支付（铸造+支付同一笔）`。

验收点：
- 展示 `digest / status / explorer`。
- 成功时可看到 `Receipt objectId`。
- 事件流中可看到 `InvoicePaid` / `ReceiptMinted`。

### 3.3 赎回（`#/redeem`）

1. 进入赎回页。
2. 展示 Banner：MVP 默认 T+1，Instant 仅路线图。
3. 执行 `按数量赎回` 或 `一键全部赎回`。

验收点：
- 交易反馈包含 `digest / status / explorer`。

### 3.4 商户领取收益（`#/merchant/claim`）

1. 点击“领取收益”。
2. 如失败，页面会显示可能原因（权限、非收益接收方、配置错误、RPC 异常）。

### 3.5 指标看板（`#/merchant/metrics`）

1. 点击“刷新数据”。
2. 展示：
   - 支付转化率
   - 已支付/待支付 GMV
   - `getTotalSupply()`
   - `getTotalSupplyByCoinType(type)`

## 4. Agent 演示（推荐）

1. 打开右下角“智能助手”。
2. 输入：`请一键连续执行剧本`。
3. 在“推荐动作”点击“运行剧本”。
4. 按提示依次钱包签名。

剧本会串行执行：
- 创建商品
- 创建账单
- Mint+Pay
- Burn
- Claim

## 5. 本地自治模块演示（新）

1. 打开 `#/automation` 页面。
2. 输入任务目标：`整理 Downloads，按类型归档并输出报告`。
3. 确认命令白名单前缀（如 `node,git,ffmpeg,tar,pnpm`）。
4. 点击“生成计划”。
5. 查看“安全守卫状态”：
   - 是否有阻断原因
   - 是否存在高风险步骤审批要求
6. 点击“执行计划”。
7. 点击“导出 Markdown”。

说明：
- 本模块采用 `计划 -> 守卫 -> 执行` 三段式。
- 不替换现有 `stable-layer-sdk` 与 `@mysten/sui` 主交易链路。

## 6. 历史记录与导出

1. 打开 Agent 的“时间线/历史”面板。
2. 点击“导出 Markdown”。
3. 导出的 `.md` 可直接作为演示附件。

说明：
- 时间线已持久化到 `localStorage`。
- 导出内容为 Markdown 结构，便于复盘与团队协作。

## 7. 常见问题说明

### 7.1 为什么 USDC 对象列表会变化？

- 在真实链模式下，钱包里的 coin 可能被拆分/合并，选择器会按余额重新组合 coin，因此列表可能变化。
- 在 Smoke 模式下，使用稳定模拟 coin id，避免“每次刷新都乱跳”。

### 7.2 Smoke 是什么？

- Smoke（冒烟）是最小链路验证模式，重点是快速验证流程“通不通”。
- 它不是生产级真实性证明，只用于演示连续性和容错。

### 7.3 怎么证明不是玩具？

- 关键交易都可点开 Explorer 复核。
- 页面有 REAL/SMOKE 模式标识。
- 配置不完整时，关键交易按钮会被禁用并提示缺口。
- 本地自治模块有守卫策略与可导出审计日志。

## 8. 录屏建议

2. 再录 3-4 分钟主线闭环。
